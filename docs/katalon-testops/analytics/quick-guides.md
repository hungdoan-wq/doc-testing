# Role-Based Workflow Guides

Reading time: 6 minutes

Reports & Analytics provides different value to different roles. Instead of reading every dashboard and report guide sequentially, these workflow guides curate documentation to match your responsibilities—helping you focus on what matters for your role and get to proficiency faster.

## Why Role-Based Workflows?

Generic feature-by-feature documentation forces you to figure out which features matter for your job. These workflow guides do that work for you:

- Curated learning paths optimized for your responsibilities (not generic walkthroughs)

- Phase-based progression building skills incrementally (foundations → intermediate → advanced)

- Task-focused approach connecting features to daily workflows

Whether you're monitoring team quality metrics, executing tests, automating CI/CD pipelines, or planning releases, there's a guide tailored to your needs.

Start with Universal Getting Started: Before jumping to your role-specific guide, complete the three foundational documents below. They provide core concepts that all roles need.

## Universal Getting Started (All Roles)

Regardless of your role, start here:

- [Core Concepts](/docs/getting-started/core-concepts) - Understand dashboards, reports, and analysis scopes

- [Report Types Overview](/docs/getting-started/report-types) - Learn what each report category provides

- [Filters & Analysis Scope](/docs/getting-started/filters-and-scope) - Master the filtering system that powers all tools

After completing these foundations, jump to your role-specific guide below to continue your learning journey.

## How These Guides Work

Each role-based workflow guide follows the same structure to support your learning journey:

### 1. Primary Goals & Outcomes

Clear objectives aligned with your role's responsibilities. For example, a QA Manager guide focuses on team oversight and reporting, while a Manual Tester guide emphasizes test execution and failure investigation.

### 2. Recommended Learning Path

Phase-based progression:

- Phase 1: Essential daily tools you'll use immediately

- Phase 2: Intermediate features expanding your capabilities

- Phase 3: Advanced workflows and optimizations

Each phase builds on the previous one, so you develop skills incrementally without overwhelm.

### 3. Common Tasks & Locations

Quick-reference table mapping your daily tasks to specific dashboards and reports. Use this as a cheat sheet once you've completed the learning path.

### 4. Visual Journey Map

Mermaid workflow diagram showing how you'll navigate from task to tool to insight. This gives you the "big picture" of how everything connects.

# Automation Engineer Workflow Guide

## Your Role in Reports & Analytics

As an Automation Engineer, SDET, or Test Automation Developer, you use Reports & Analytics to monitor automated test execution in CI/CD pipelines, identify and fix flaky tests, analyze test performance, and optimize configuration coverage. This guide provides a technical, systematic learning path to help you master the platform in 3-4 weeks.

## Your Primary Goals

### Goal 1: Monitor Automated Test Execution in Real-Time

Outcome: Immediate visibility into active CI/CD pipeline executions and test progress

Key Capabilities:

- Track active test runs across multiple pipelines in real time

- View test execution status (running, passed, failed) during CI/CD runs

- Identify pipeline failures immediately for rapid response

- Monitor execution duration and performance trends

Features You'll Use:

- Live Monitor Dashboard for active test run tracking

- Test Run Analysis report for execution history and trends

- Filters for configuration, environment, and pipeline-based views

### Goal 2: Identify and Fix Flaky Tests with Stability Metrics

Outcome: Reduce flaky test maintenance burden through data-driven prioritization

Test Stability Intelligence identifies flaky tests BEFORE they impact team productivity—reducing maintenance burden 40-60% through targeted stabilization.

Key Capabilities:

- Identify flaky tests using Probabilistic Flakiness Score (PFS)

- Analyze failure patterns and intermittent failures

- Prioritize stabilization efforts by impact (execution frequency × flakiness)

- Track stability improvements over time

Features You'll Use:

- Test Stability Intelligence for PFS scoring and flaky test detection

- Test Failure Analysis report for pattern identification

- Stability trends for historical flakiness tracking

- AI Test Failure Analysis for root cause suggestions

### Goal 3: Analyze Test Performance and Execution Duration

Outcome: Optimize test suite execution time and identify performance bottlenecks

Key Capabilities:

- Track test execution duration trends over time

- Identify slow tests consuming pipeline time

- Analyze performance across configurations and environments

- Optimize test parallelization and resource allocation

Features You'll Use:

- Test Run Analysis report for duration metrics

- Performance widgets for execution time trends

- Configuration Coverage report for execution distribution analysis

- Duration-based filters for identifying slow tests

### Goal 4: Optimize Test Coverage Across Configurations

Outcome: Ensure comprehensive coverage across browsers, devices, OS combinations

Key Capabilities:

- Track configuration coverage (browsers, OS, devices)

- Identify untested configuration combinations

- Validate cross-platform test distribution

- Ensure requirement coverage through automated tests

Features You'll Use:

- Configuration Coverage report for coverage matrix visualization

- Requirement Coverage report for automated test linkage

- Test Case Health Analysis for automation progress tracking

- Automation Progress report for automation rate trends

# Manual Tester Workflow Guide

## Your Role in Reports & Analytics

As a Manual Tester (or QA Tester/Test Analyst), you use Reports & Analytics to navigate test results, investigate failures quickly with AI assistance, create defects with complete context, and validate requirement coverage. This guide provides a focused learning path to help you master these execution workflows in 2-3 weeks.

## Your Primary Goals

### Goal 1: Navigate Test Results Efficiently

Outcome: Find and understand test execution results across manual and automated tests

Key Capabilities:

- View test results by project, release, test suite

- Filter results by status (passed, failed, incomplete)

- Understand test execution history and trends

- Identify which tests need attention

Features You'll Use:

- Test Results section with Test Result Analysis report

- Test Run Analysis report for execution history

- Filters for status, test suite, and release filtering

### Goal 2: Investigate Test Failures Systematically

Outcome: Quickly identify root causes of test failures using AI assistance

Key Capabilities:

- Use AI Test Failure Analysis for automated triage

- Review failure screenshots, logs, and stack traces

- Identify patterns in recurring failures

- Determine if failure is test issue, environment issue, or product defect

Features You'll Use:

- Test Failures section with AI Test Failure Analysis

- Test Result details with screenshots, logs, attachments

- Test Stability Intelligence for flaky test identification

- Failure History for pattern recognition

### Goal 3: Create and Track Defects from Failures

Outcome: Report defects efficiently with complete context and track resolution

Key Capabilities:

- Create defects directly from test failures

- Auto-populate defect details (steps, environment, screenshots)

- Link defects to requirements and test cases

- Track defect status and resolution progress

Features You'll Use:

- Test Failures with Create Defect action

- Defects section for defect tracking dashboard

- Jira/Azure DevOps integration for bidirectional sync

- Requirement linkage for traceability

### Goal 4: Understand Requirement Coverage Status

Outcome: Know which requirements are validated and which need testing

Key Capabilities:

- View requirement coverage progress

- Identify untested or partially tested requirements

- Understand test case to requirement mapping

- Validate coverage completeness before release

Features You'll Use:

- Coverage Reports with Requirement Coverage report

- Test Case Health Analysis for coverage by requirement

- Requirement Traceability for test linkage view

## Recommended Learning Path

### Phase 1: Core Execution Workflows (Weeks 1-2)

Goal: Master daily test execution, result navigation, and failure investigation

#### Test Result Navigation & Basic Investigation

Learning Objectives:

# Product Owner Workflow Guide

## Your Role in Reports & Analytics

As a Product Owner, Product Manager, or Business Analyst, you use Reports & Analytics to track requirement validation, assess release readiness, monitor product quality, and communicate quality status to stakeholders. This guide provides a streamlined learning path optimized for non-technical product roles—the fastest proficiency of all roles.

## Your Primary Goals

### Goal 1: Track Requirement Coverage & Validation

Outcome: Ensure all requirements have test coverage before release

Key Capabilities:

- Track coverage percentage across all requirements

- Identify gaps in test-to-requirement traceability

- Monitor requirement validation progress across sprints

- Prioritize test creation based on coverage gaps

Features You'll Use:

- Requirement Coverage Report - Coverage percentage, gap analysis, and risk identification

- Requirement Traceability Report - Complete requirement lifecycle tracking from creation to validation

- Project Dashboard Requirements Tab - Real-time requirement validation status and trends

### Goal 2: Assess Release Readiness & Quality Gates

Outcome: Make data-driven go/no-go release decisions

Key Capabilities:

- Assess release readiness against configurable quality gates

- Monitor release health trends (pass rate, defect density, coverage)

- Document release decisions with objective metrics

- Communicate release status to leadership and stakeholders

Features You'll Use:

- Release Health Dashboard with Release Readiness Indicator - Visual Go/Caution/Stop signals for release decisions

- Quality Gates Configuration - Customizable thresholds for pass rate, coverage, and defect density

- Release Metrics Report - Historical release quality comparison and trend analysis

### Goal 3: Monitor Product Quality Trends

Outcome: Track product quality trajectory over time

Key Capabilities:

- Monitor pass rate trends across releases and sprints

- Identify quality improvements or degradations early

- Analyze defect trends and resolution velocity

- Validate quality investments and process improvements

Features You'll Use:

- Analytics & Trends Dashboard - Pass rate trends, failure rate patterns, and quality trajectory

- Defect Trend Analysis Report - Defect density, age distribution, and resolution metrics

- Project Dashboard Release Quality Tab - Multi-release quality comparison and historical trends

### Goal 4: Communicate Quality Status to Stakeholders

Outcome: Executive-friendly quality summaries for non-technical stakeholders

Key Capabilities:

- Generate automated weekly quality summaries for leadership

- Create release readiness presentations with supporting data

- Share secure, time-limited dashboard/report links externally

- Export quality metrics to PDF/CSV for board meetings

Features You'll Use:

- AI Executive Briefing - Auto-generated 3-part summaries (Quality Snapshot, Risk Assessment, Recommendations)

- External Report Sharing - Secure, time-limited links for external stakeholders with customizable expiration

- Project Dashboard Overview - High-level quality metrics optimized for executive consumption

## Your Primary Goals

### Goal 1: Monitor Team Testing Progress

Outcome: Real-time visibility into testing velocity, execution volume, and team productivity

Key Capabilities:

- Track daily test execution across manual and automated efforts

- Monitor pass/fail trends to identify quality trajectory

- Identify bottlenecks in test execution or defect resolution

Features You'll Use:

- Live Monitor Dashboard for active test run tracking

- Analytics & Trends Dashboard for pass rate trends and test activity

- Test Run Analysis Report for execution volume over time

### Goal 2: Analyze Quality Trends

Outcome: Data-driven insights into product quality over time

Key Capabilities:

- Identify quality improvements or degradations across sprints

- Detect flaky tests consuming team time

- Analyze failure patterns to prioritize improvements

Features You'll Use:

- Analytics & Trends Dashboard for pass rate trend analysis

- Test Stability Intelligence for probabilistic flakiness detection

- Test Failure Analysis Report for failure pattern identification

### Goal 3: Facilitate Release Decisions

Outcome: Objective quality data for go/no-go decisions

Key Capabilities:

- Assess release readiness against quality gates

- Communicate risks and mitigation plans objectively

- Document release decisions with supporting metrics

Features You'll Use:

- Release Health Dashboard with Release Readiness Indicator

- Requirement Coverage Report for coverage gap analysis

- Quality Gates configuration for custom thresholds

### Goal 4: Report to Stakeholders

Outcome: Executive-friendly summaries of quality status

Key Capabilities:

- Generate weekly leadership updates automatically

- Create release readiness presentations with supporting data

- Share secure, time-limited dashboard links with external stakeholders

Features You'll Use:

- AI Executive Briefing for auto-generated 3-part summaries

- External Report Sharing for secure stakeholder access

- Project Dashboard Release Quality tab for historical trends
